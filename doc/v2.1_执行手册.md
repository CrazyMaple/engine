## 1. 目标与边界

### 1.1 唯一目标

把 `engine/` 收缩为**纯 Actor 引擎**：只承担 Actor 生命周期、位置透明通信、虚拟 Actor 激活、最小集群成员感知、跨节点消息契约。

### 1.2 唯一判定标准

> 这段代码是否直接服务于 Actor 生命周期管理？

Actor 生命周期 = **创建 · 激活 · 寻址 · 消息传递 · 监管 · 停止 · 死信**。

| 算"Actor 生命周期管理" | 不算（应剔除/下迁） |
|---|---|
| 创建（Spawn/Props） | 消息分发模式（Router、PubSub） |
| 激活（Grain 自动激活） | 集群运维（RollingUpgrade、Canary、MultiDC、Federation） |
| 寻址（PID、位置透明） | 集群拓扑健康（SplitBrain、Migration） |
| 消息传递（Mailbox / Dispatcher / Remote） | 传输层优化与安全实现（Encryption、Signer、Fragment、ZeroCopy） |
| 监管（Supervisor Directive） | 日志基础设施（Aggregator、BroadcastSink、RingBufferSink） |
| 停止与优雅关闭（Shutdown、Signal） | 可观测性增强（Profile、SchedulingMetrics 上报层） |
| 死信与死信队列（DeadLetter） | 服务发现具体实现（Consul/Etcd/K8s/Gossip） |
| 跨节点消息契约（proto） | 集群运维入口（Federation、Canary 流量分流） |

### 1.3 不变的对外约定

- Proto.Actor 风格的 PID / Context / Supervisor / Props API。
- 位置透明语义。
- 跨节点消息契约（`proto/` 四份 .proto）。

### 1.4 参考目录规则

`better/` 与 `engine_sample/` 同等视为只读参考：

1. 不参与编译；
2. 不参与功能完成度审核；
3. 不参与测试统计；
4. 不计入 LOC；
5. 不参与 doctor deps（必须写入 `exclude_paths` 配置）；
6. 只读，新代码不得 import；
7. 目录下任何嵌套 `go.mod`（包括 `better/protoactor-go-dev/examples/*/go.mod` 等大量子 module）一律按目录前缀整体排除，不参与 v1.13 任何 `go test ./...` 与完成度统计；具体清单以 Phase 0 `find better engine_sample -name go.mod -print | sort` 扫描结果为准（见 §3 Phase 0 基线扫描）。代表性路径（仅示例，不构成穷举）：
   - `better/protoactor-go-dev/`（含其下大量 `examples/*/go.mod` 嵌套 module）
   - `engine_sample/basics/`、`engine_sample/centerserver/`、`engine_sample/enginemessage/`、`engine_sample/hf/`、`engine_sample/message/`

v1.13 测试只覆盖 `engine/`、`gamelib/`、`tool/` 三个 module；执行 `go test` 必须分别 `cd` 进三个目录，**不允许使用 `find . -name go.mod` 全仓自动发现**。

Phase 4 收口时把容器根 `code/engine/CLAUDE.md` 的"better/ 目录规则"段标题改为"参考目录规则（better/、engine_sample/）"，规则文本复用同一份 7 条。

### 2.5 接口型保留点

#### 2.5.1 Mailbox 扩展契约

`actor.Mailbox` 主接口保持不变。新增四个**可选扩展接口**，外部 mailbox 实现按需选择：

```go
// engine/actor/mailbox.go

// SchedulerAware 邮箱可接收调度器注入
type SchedulerAware interface {
    SetScheduler(Dispatcher)
}

// OwnerAware 邮箱可接收所属 Actor PID 注入（用于背压事件）
type OwnerAware interface {
    SetOwnerPID(*PID)
}

// EventStreamAware 邮箱可接收事件流注入（用于发布背压等事件）
type EventStreamAware interface {
    SetEventStream(*EventStream)
}

// BatchAwareMailbox 邮箱可接收批处理回调注册。
// 注：actor 侧契约仍为 BatchActor.BatchReceive(ctx Context, []interface{})；
// Mailbox 不直接持有 actor 接口，二者通过 RegisterBatchHandler 传入的闭包桥接。
type BatchAwareMailbox interface {
    RegisterBatchHandler(func([]interface{}))
}
```

`engine/actor/props.go` spawn 路径用接口断言替换对私有 mailbox 类型的硬编码断言：

```go
// engine/actor/props.go：spawn 注入逻辑
if sa, ok := cell.mailbox.(SchedulerAware);    ok { sa.SetScheduler(...)    }
if oa, ok := cell.mailbox.(OwnerAware);        ok { oa.SetOwnerPID(...)     }
if ea, ok := cell.mailbox.(EventStreamAware);  ok { ea.SetEventStream(...)  }
if bm, ok := cell.mailbox.(BatchAwareMailbox); ok {
    if ba, ok := actor.(BatchActor); ok {
        bm.RegisterBatchHandler(func(msgs []interface{}) {
            ba.BatchReceive(cell, msgs)
        })
    }
}
```

外迁到 `gamelib/actor/mailbox/` 的四种 mailbox 通过按需实现这四个扩展接口保持调度、背压、批处理行为等价。`BatchActor` 契约保持现有定义不变。

#### 2.5.2 Remote 安全接口

```go
// engine/remote/cipher.go（新建文件，仅放接口）

type MessageCipher interface {
    Encrypt(plaintext []byte) ([]byte, error)
    Decrypt(data []byte) ([]byte, error)
    KeyID() uint32
}
```

```go
// engine/remote/signer.go（仅放接口）

type MessageSigner interface {
    Sign(payload []byte) []byte
    Verify(payload, sig []byte) bool
    // SignatureSize 返回此 signer 产出的签名字节长度。
    // 约束：
    //   - 返回值必须 > 0；返回 0 视为禁用签名（构造时报错或拒绝注入）。
    //   - 接收路径若 len(data) < SignatureSize() 必须拒绝。
    //   - 发送路径 append 的签名长度必须等于 SignatureSize()。
    //   - 实际产出的签名长度若与 SignatureSize() 返回值不一致，视为实现 bug，
    //     fake / test 实现尤其需要保证两者严格一致。
    SignatureSize() int
}
```

`Remote.Cipher` / `Remote.Signer` / `EndpointManager.cipher` / `EndpointManager.signer` 字段类型统一为接口。`engine/remote/remote.go` 的 HMAC 拆包逻辑改为 `sigSize := signer.SignatureSize()`。

`engine/remote/conn_pool.go` 当前**仅有 `signer` 字段，无 `cipher` 字段**，且 `addEndpoint()` 未传播 cipher。Phase 2 必须**新增 `cipher` 字段并在 `addEndpoint()` 中同步传播**：

```go
// engine/remote/conn_pool.go
type connPool struct {
    signer MessageSigner   // 类型从 *MessageSigner 改为接口
    cipher MessageCipher   // 新增
    ...
}

// addEndpoint 当前是无参方法
func (p *connPool) addEndpoint() {
    ep := NewEndpoint(p.address)
    ep.signer = p.signer
    ep.cipher = p.cipher   // 新增
    ...
}
```

创建 connPool 的位置必须把 EndpointManager 的 signer / cipher / codec / tls 配置同步传入。若当前 connPool 实际未接入发送路径，Phase 2 必须扫描并决定"接入、删除或暂留但修正配置传播"，**不允许只改字段类型不改传播逻辑**。

具体实现（AES-GCM / CipherRing / X25519 派生 / HMAC）外迁 `gamelib/remote/security/`。

#### 2.5.3 Cluster Provider 推荐最小接口（最终以 ADR 001 为准）

> 下方代码块是**推荐最小形状**，仅供 ADR 001 起草时参考。Provider 接口的最终签名（包括方法集、`onChange` 回调语义、扩展接口划分）一律以 `doc/adr/v1.13_001_cluster_provider.md` 拍板结果为准；实施者**不得绕过 ADR 直接照本节代码落地**。

```go
type Provider interface {
    Start(clusterName string, self *Member, onChange func([]*Member)) error
    Stop() error
}
```

`Register / Deregister / GetMembers` 若保留，作为可选扩展接口（`RegistrableProvider` / `ListableProvider`），不强制 Provider 实现全部实现。

ADR 001 必须拍板：

- `Register / Deregister / GetMembers` 是保留主接口、提为扩展接口、还是删除。
- `onChange` 回调使用全量快照还是增量事件（`MemberJoined` / `MemberLeft` / `MemberDead`）。
- `StaticProvider` 仅承担静态成员快照，不承担 gossip 传播。
- Provider 启动失败时 `Cluster.Start()` 行为：**Phase 3 删除 gossip 后必须 fail-fast**，不允许隐式 fallback。
- `ClusterTopologyEvent` 是否改名：**默认保留现有命名**。

## 3. Phase 框架

### 3.A 测试门禁口径（贯穿全部 Phase）

- **Phase 收口（Phase 0/1/2/3/4 验收）必须**：engine / gamelib / tool 三 module 分别 `cd` 进去执行 `go build ./...` + `go test ./...` 全部通过，不接受任何放宽。
- **Phase 内中间 PR 可放宽**：仅跑受迁移影响的包（如 Phase 1 router 任务可只跑 `gamelib/router/...` + `tool/example/...`），但每个中间 PR 仍须通过 `doctor deps --check-baseline`。
- 测试范围严格限于 `engine/` / `gamelib/` / `tool/` 三个 module；**永久排除** `better/` 与 `engine_sample/` 全部目录（含其下任意嵌套 `go.mod`，例如 `better/protoactor-go-dev/examples/*` 下的子 module），不允许列举式排除遗漏。**禁止使用 `find . -name go.mod` 全仓自动发现**。

每个 Phase 结束保证：

- 上述测试门禁通过（三 module 全量 `go build ./...` + `go test ./...`）；
- `tool/cmd/engine doctor deps --root ..` 零违规；
- `doctor deps --check-baseline` 不出现新增的待删除引用 / 文件 / 符号。

#### §3.0.A · `doc/v1.13_dep_baseline.json` schema

`mode` 字段控制 `--check-baseline` 校验严格度：`"freeze"` 用于 Phase 1-3；`"zero"` 用于 Phase 4。

**路径匹配语义（doctor deps 必须遵守）**：

- 所有路径条目均为**仓库根（即 `code/engine/`）相对路径**，不接受绝对路径或 module 根相对路径。
- `exclude_paths`：以"/"结尾视为目录前缀，**目录前缀匹配且递归生效**（例如 `better/` 命中 `better/anything/sub.go`、`better/protoactor-go-dev/examples/x/go.mod` 等任意深度子项）；不以"/"结尾的条目视为精确文件路径匹配。
- `import_baseline` 的 value 路径列表：每项为**精确文件路径**，按字符串等值比较，不做前缀展开。
- `file_baseline.should_be_removed`：以"/"结尾视为目录条目，**目录递归检查**（目录本身或其下任意文件存在即判违规）；不以"/"结尾视为精确文件路径，**精确匹配**（仅当此完整路径存在时判违规）。
- `symbol_baseline` 的 key 为 import path，value 描述该包内待清零的导出符号 / 关键词 / 常量；扫描范围受 `exclude_paths` 影响。

```json
{
  "version": "v1.13",
  "mode": "freeze",
  "exclude_paths": [
    "better/",
    "engine_sample/"
  ],
```

## 4. 风险门禁

### 4.1 硬门禁（CI 必须通过）

- `engine` 不得 import `gamelib` 或 `tool`。
- `engine` 不得包含 `router` / `pubsub` / `cluster/canary` / `cluster/federation` 目录或文件。
- `engine/remote` 不含具体 AES-GCM / HMAC 实现，仅保留接口和发送/接收调用点。
- `engine/remote` 不含 `hmacSize` 等算法固定常量。
- `engine/network` 不含 KCP 具体实现。
- `engine/cluster` 不内嵌 gossip / splitbrain / federation / canary / rolling upgrade / multi DC / migration 任一实现。
- `engine/grain` 仅通过 `cluster.GetMemberForIdentity()` 获取归属节点；`forbidden_keywords: ["gossip", "Gossip", "splitbrain", "SplitBrain"]` 命中数为 0。
- 测试门禁分两档（与 §3.A 保持一致）：
  - **Phase 收口**：engine / gamelib / tool 三 module 全量 `go build ./...` + `go test ./...` 必须通过，不允许放宽。
  - **Phase 内中间 PR**：可仅跑受迁移影响的包，但 `doctor deps --check-baseline` 必须通过。
- Phase 1-3 每个 PR：`doctor deps --check-baseline` 通过（待删除引用 / 文件 / 符号只减不增）。
- Phase 4：`doctor deps --check-baseline` 三类基线全部清零或满足反向门禁。

### 4.2 软指标（仅观察，不卡线）

- engine 源码行数（目标 ≤10 000 行，作为参考；不强制）。
- benchmark 数据（关注核心路径延迟、分配、race 是否新增；不卡固定百分比）。
- 导出符号数量与依赖数量精简前后对比（写进 `v1.13_完成度审核.md`）。

### 4.3 不接受的行为

- 跨层 type-alias shim（`type X = gamelib.X` 在 engine 内出现）。
- 为已删除代码保留兼容包装。
- 在 engine 内重新引入"性能优化 / 集群运维 / 消息分发模式 / 日志基础设施"任一类代码，无论体量多小。
- 跳过 Phase 0 的 doctor deps 工具能力建设直接进 Phase 1。
- Phase 1 调用方迁移清单出现"等 N 文件"等模糊措辞。
- Phase 3 删除 gossip 后保留 fallback 路径。
- Phase 4 `ClusterConfig.Gossip*` / `SeedNodes` 既不删除也不标 deprecated 的第三态；同样适用于 `WithSeedNodes` / `WithGossipInterval` 配置方法。
- 使用 `find . -name go.mod` 全仓自动发现 module 跑测试（必须显式只跑 `engine/` / `gamelib/` / `tool/` 三个；永久排除 `better/` 与 `engine_sample/` 全部目录及其下任意嵌套 `go.mod`，不接受列举式排除遗漏）。
- 引入丢失 `Context` 的批处理 API；批处理契约必须保持 `BatchActor.BatchReceive(ctx Context, []interface{})` 不变。
- Phase 2 改 `connPool` 字段类型时不同步修正 `addEndpoint()` 的 cipher / signer 传播逻辑（导致池化 endpoint 丢失加密配置）。
- log 聚合落 `tool/dashboard/logstore/`（必须落 `tool/logstore/` 共享路径，避免 `tool/cmd/engine/runtime.go` 反向依赖 dashboard 子域）。
